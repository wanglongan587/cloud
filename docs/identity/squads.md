# 小队与定向加入

[English](squads.en.md) | 中文

小队引用当前工作区的人类成员和 Space Agent，不复制成员资格，不授予项目、模型、Git 或运行时权限。P1 只管理编组，不注册可执行 Team 目标，选择 leader 也不会启动运行。正式依据为 specs 的[小队根决策](https://github.com/ora-space/specs/blob/main/decisions/cloud/squad/0-workspace-scoped-human-agent-squads.md)和[定向加入与签发者失权](https://github.com/ora-space/specs/blob/main/decisions/cloud/tenancy/20261027-squad-targeted-joining-and-inviter-revocation.md)；ADR 生命周期和直接证据在 specs 单独维护。

## 维护与历史

有效工作区成员可以创建、读取小队，创建者原子成为首位维护者。修改、添加已有成员/Agent、维护职责、归档和设置 leader 只允许当前管理员或本队有效人类维护者。创建人没有永久权利，所有维护者离开也不会阻止管理员接管。写操作携带读取时的小队版本，冲突后重新读取。

编组以 user/agent 类型和稳定 ID 区分。每个对象可加入多个小队，一队内最多一条有效关系；结束关系保留来源、时间、职责及维护权事实。重新加入建立新关系，不复活旧维护权。归档无恢复接口，结束全部关系和 leader，历史详情仍受当前租户成员权限保护。

leader 必须是同工作区的活动 Space Agent，设置时原子补齐入队关系。移除现任 leader 必须显式清除配置；更换后原 Agent 保留普通关系。Agent 退役时数据库触发器结束全部有效编组并清除 leader，重新安装不恢复。用户全局停用/删除、租户成员停用由同事务触发器关闭对应范围的有效人类编组，保持已准入运行不变。

## 邀请、审批与来源

只有管理员能签发外部邀请或批准申请。链接目标在签发时规范化、去重、冻结，最多 20 个当前同租户活动小队；兑换只读取服务端冻结目标，不接收客户端授予目标。普通邀请目标为空。

匿名预检仅返回类型和状态，签发者失权或目标失效均为 unavailable。登录且身份有效后才返回工作区、邀请者、目标小队名和本人的状态，提交在原事务重验。已有成员只缺编组时仍须显式确认。新建/恢复资格和全部目标编组、消费或审批结果同事务提交；任一目标失效不产生部分加入。

没有资格建立/恢复也没有新增编组时，不消费、不发加入通知、不记来源；纯入队消费单次邀请但只记录编组来源。邀请、审批、企业目录共用加入规则；工作区来源仅在真实资格变更时追加。申请冻结原目标，同一用户/租户只保留一个 pending；同目标重复返回原请求，不同目标冲突。签发者失权停止新申请，已经提交的申请仍可由另一位当前管理员独立决定。

管理员降级、成员失效、用户全局停用或删除会持久设置尚可使用链接的 invalidated_at，复权不能清空该事实。小队归档同样终止指向它的可用入口。最后管理员保护失败时整个事务回滚，不附带失效任何链接。

## 升级与回滚边界

这是需要停止旧写入者的升级，不能滚动混跑旧 Cloud：

1. 备份数据库并在隔离副本演练；从入口暂停所有加入和成员操作，停止全部旧 Cloud 实例及其自动重启/扩容来源。确认没有旧实例仍可访问数据库。
2. 使用候选二进制执行 `cloudctl migrate`，保留旧迁移 checksum，不重建真实数据库。迁移或校验失败时保持入口关闭。
3. 全量更新 Cloud、Gateway 与前端，再启动新 Cloud 并通过 `CheckSchema`。旧二进制会因未知迁移拒绝启动；这个启动检查不能阻止迁移前已运行的进程，因此第 1 步不可省略。
4. 验证跨租户拒绝、预检最小响应和受控邀请加入后，统一恢复入口。失败时保留停写状态；不得启用旧二进制绕过新授权规则。需要恢复备份时先评估并保全升级后写入。

迁移为旧链接和 pending 申请设置空目标，保留合法签发者的原摘要、期限和状态，当前失权者的可用链接永久失效；不推测升级前失权后复权的历史。`join_policy_activation` 记录一次启用时间，不回填演示小队或工作区加入来源。迁移编号在合并时按 main 顺延。

列表与详情从真实 REST 状态投影；提交后的成员/插件失效事件使小队及相关选择器重读。断线重连、重新聚焦和切换工作区重新验证；SSE 不是授权权威。待兑换邀请不冒充用户名，待审批申请不计入成员数量。
